# voice_lines_vox

Working data for the Hila (`rb21`) voice-line replacement: Miranda Lawson clips from
`references/Голос Лоусон.7z` and purpose-authored Mira Lawson takes from
`references/LAWSON VOICE (PAYDAY 2).7z`, mapped to Hila's PAYDAY 2 lines. The only shipped pack is the id-keyed
stream pack, `dist/Miranda/Miranda_Lawson_VO_over_Hila_Stream.zip`; its install and format contract is
[`docs/pd2-voice-mod-install.md`](../docs/pd2-voice-mod-install.md) §7.

## Slot rule: Call vs Follow

- `Call <Name>` (rb21 `CH_Name`, summon a teammate) maps to the intent slot `call_teammate.hey_you`.
  A named callout ("Hey, Sokol!", "Bonnie.") becomes generic because Miranda does not know the
  heisters' names. The available source has no "hey", so the shipped clip is one emphatic **"You!"**.
- `Follow` / `On me.` (rb21 squad-move) maps to `move.on_me` — its clip scored below 8 and no take
  exists in either source archive, so the slot is removed and vanilla Hila plays there (2026-11-25).
  Call must not use it either.

## The stream tables (Rust, Old Hoxton)

A pack writes the file the game streams, so `slot → bank → id` is the table a VO build needs;
one per target heister, tracked, generated by `tools/build_stream_tables.py` (`make -sC
tools/pd2-las voices_tables`) and pinned to the zips by `tests/test_stream_tables.py`:

| Table (`targets/`) | Target | Rows written by the pack |
| --- | --- | --- |
| `rust_shared_regular_vox.csv` | Rust, `regular_vox` (switch `rb16`) | 315 = `Geralt_VO_over_Rust_Stream.zip` |
| `old_hoxton_shared_regular_vox.csv` | Old Hoxton, `regular_vox` (switch `rb5`) | 324 = `Arivus_VO_over_Hoxton_Stream.zip` |
| `rust_dedicated_char_rust.csv` | Rust, `char_rust` — **measured** in `references/Marine VO for Rust.7z.001` | none (no id shared with the table above) |

Both leave the 27 Wwise Vorbis ids and the slots without a take vanilla, and both name the
folder a *dedicated* bank would be (`char_rust`, `char_hoxton`). Why the two banks are not
interchangeable, and the open question of which one Rust barks from:
[`docs/pd2-voice-stream-tables.md`](../docs/pd2-voice-stream-tables.md) (D73).

**The re-key (D76).** `make -sC tools/pd2-las voices_char_rust` writes the same Geralt takes into
`soundbanks/streamed/char_rust/` instead of `regular_vox/`, so the pack would change Rust alone. It
takes every id from [`geralt/char_rust_ids.csv`](geralt/char_rust_ids.csv) — a **template with no
rows** — and refuses to build until a source names each one, because the measured bank says which
files exist, not which line each file is. Fill that map (an extract of the game's
`soundbanks/streamed/char_rust`, decoded line by line) and the next build produces the re-keyed
pack; `dist/Geralt/Geralt_VO_over_Rust_Stream.zip` stays the shared-bank pack until then.

The community `regular_vox` sheet the user supplied is **not** that map: it is the shared
bank, and its speakers are the vanilla crew. It is imported into [`sheets/`](sheets/README.md)
as a reproducible table with slot *leads* (D77); nothing in `dist/` is built from a lead.

## Regenerate

```bash
python3 tools/fit_hila_intents.py         # hila_intent_fit.csv + hila_slot_pieces.csv
python3 tools/hila_voice_clips.py         # hila_slot_pieces.csv only: the picks, nothing packaged
python3 tools/build_hila_stream_mod.py    # the .stream pack, named by voice-line id
```

`make -sC tools/pd2-las voices_stream` builds the sole shipped voice pack and prints its state.
The former BeardLib `SoundsModule` pack was dropped on 2026-11-25 (D61); its historical packaging
analysis is retained in [`docs/pd2-voice-mod-install.md`](../docs/pd2-voice-mod-install.md) §§1–6.

Since 2026-11-25, two more packs of the same route ship for other characters, built by
`tools/build_character_stream_mod.py` from purpose-authored bark sets:

| Pack | Source | Coverage |
| --- | --- | --- |
| `dist/Geralt/Geralt_VO_over_Rust_Stream.zip` | `references/GERALT VOICE (PAYDAY 2).zip` ("Геральт", CP866 file names) | the 29 slots the set carries (315 `.stream` files over the shared ids); alternate takes (`civ.down (2..4)`, `mask.go (2)`, `inspire.faster (2)`) are left unused, noted in `geralt/slot_picks.csv` |
| `dist/Arivus/Arivus_VO_over_Hoxton_Stream.zip` | `references/ARIVUS VOICE (PAYDAY 2).zip` (+ one borrowed file) | the 18 slots the set carries, plus `call_teammate.hey_you` ← the Geralt 'Hoxton.' callout borrowed from the GERALT archive per the user's 2026-11-25 decision, so that slot is Geralt's voice too |

Both write the **same shared `regular_vox` voice-line ids** as the Hila pack — they are alternatives,
not companions; install only one of the three. Slots with no take in the pack's source set are left
vanilla (the pack records `no take in <archive>; left vanilla` per id in its manifest). The Geralt pack
ships `kill.taser`/`mark.taser` although those slots scored below 8 for the Hila pick: the removal logic
was Hila-specific, and purpose-authored takes are shipped as they are. Neither pack has been heard in game.

Working data: `geralt/slot_picks.csv` (29 picks) and `arivus/slot_picks.csv` (19 picks) — whole takes
with 30 ms of each file's leading silence and 50 ms of its trailing silence kept (measure above −40 dBFS),
peak-matched to −1.5 dBFS like every other bark. Rust's bank question (whether `npc_criminal_wild_1`
barks from `regular_vox` or a `char_wild` bank) is an open in-game check, see
[the checklist](../docs/pd2-las/in-game-checklist.md).

## Package & install

Three zips ship: `Miranda_Lawson_VO_over_Hila_Stream.zip` (the Hila pack) and the two character packs
above — alternatives, install one. The Hila pack contains Wwise IMA ADPCM
`.stream` files at `soundbanks/streamed/regular_vox/<hila_id>.stream`, plus a `main.xml` marker and
`mod.txt`. The game resolves these by voice-line id; no BeardLib, XAudio API, Lua, or bark-event
mapping is needed. It is built by `tools/build_hila_stream_mod.py` using the format implementation in
`tools/pd2-las/wwise_ima.py`. Install with SuperBLT (or another BLT build) following §7 of the
[install contract](../docs/pd2-voice-mod-install.md).

The old BeardLib route keyed `<Sounds>` on PD2 bark event names, not numeric voice-line ids. Its
builder and zip were removed; the rationale and technical investigation remain as historical
context in the install document. `slot_event_ids.csv` records that investigation and is not read by
the shipped stream builder.

## Rules the tools enforce

- **No names.** No replacement clip may say "Shepard", "Commander" or "Commando" —
  `fit_hila_intents.py` filters those transcripts out and every `slot_picks.csv` window is trimmed
  before the name.
- **Level matching.** Clips target -1.5 dBFS peak, with at most +12 dB boost or -9 dB cut and no gain
  change under 0.5 dB. The bounds explain the shipped -1.9..0.0 dBFS spread.
- **Reproducible builds.** Every ffmpeg encode runs with `-fflags +bitexact`, so the same picks
  produce the same clip bytes and distribution checksum.
- **Cuts land on silence.** Windows come from `silencedetect` breakpoints plus syllable-rate
  estimates, so a trim takes the pause around a dropped word. `splits` in `slot_picks.csv` splices
  two ranges when an unwanted word sits mid-phrase (for example, `tech.drilling` drops "down" from
  "we can cut down through").

## Known gaps in the source pack

**2026-11-25 — the sub-8 slots are gone or replaced.** The semantic-fit round scored all 78 slots
against game intention. Every slot with a take in `references/LAWSON VOICE (PAYDAY 2).7z` now ships that
take, whole (30 ms of the file's own leading silence and 50 ms of its trailing silence kept), at the
usual −1.5 dBFS peak — 33 slots, including the `cop.*` / `civ.*` / `tech.fix` call-tags the archive
carries (`cop.cuffs`, `cop.kneel`, `cop.drop`, `mark.taser`, `tech.fix`). The 17 slots below 8 with no

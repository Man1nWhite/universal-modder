# voice_lines_vox

Working data for the Hila (rb21) voice-line replacement mod: Hila's PD2 lines mapped onto
Miranda Lawson voice clips from `references/Голос Лоусон.7z`.

## Slot rule: Call vs Follow

- `Call <Name>` (rb21 `CH_Name`, summon a teammate) → **"Hey, you."**
  Slot `call_teammate.hey_you`. A named callout ("Hey, Sokol!", "Bonnie.") becomes generic
  because Miranda does not know the heisters' names.
- `Follow` / `On me.` (rb21 squad-move) → **"On me."**
  Slot `move.on_me`. Follow keeps the on-me phrasing, so Call must not use it.

| `miranda_lawson/hila_intent_fit.csv` | Generated by `tools/fit_hila_intents.py`: chosen clip + score per slot. |
| `miranda_lawson/hila_slot_pieces.csv` | Build manifest: the exact ogg/time range cut for each slot. Written by `tools/hila_voice_clips.py` or by `fit_hila_intents.py` (same schema); the build record of the picks, not shipped (the stream pack carries its own `hila_stream_map.csv`). |
| `miranda_lawson/slot_event_ids.csv` | **Authoritative PD2 bark events per slot** (`slot,event_ids,note`): which events each slot stands for, `|`-separated. Kept as the record of what each line is for; nothing keys on it since the BeardLib pack was dropped (D61). |
| `miranda_lawson/hila_vorbis_ids.csv` | The 27 voice-line ids the vanilla bank streams as Wwise Vorbis (`fmt` tag `0xFFFF`), which only the Wwise encoder writes: the `.stream` pack leaves those ids vanilla instead of putting ADPCM under them. ## Regenerate

```bash
python3 tools/fit_hila_intents.py         # hila_intent_fit.csv + hila_slot_pieces.csv
python3 tools/hila_voice_clips.py         # hila_slot_pieces.csv only: the picks, nothing packaged
python3 tools/build_hila_stream_mod.py    # the clips as .stream files named by voice-line id
```

`make -sC tools/pd2-las voices_stream` builds the pack and prints its state. The BeardLib
`SoundsModule` pack this folder used to describe was dropped on 2026-11-25 (D61).

## Package & install

Two zips ship the same clips, and only one of them should be installed at a time:

- `Miranda_Lawson_VO_over_Hila_Stream.zip` — **the id-keyed route**: 858 `.stream` files
  (`soundbanks/streamed/regular_vox/<hila_id>.stream`, Wwise IMA ADPCM) and a `main.xml` with nothing
  to configure. No BeardLib, no XAudio API, no event names: a line is replaced because its file is.
  Built by `tools/build_hila_stream_mod.py`; the format is `tools/pd2-las/wwise_ima.py`.
- `Miranda_Lawson_VO_over_Hila.zip` — the BeardLib **SoundsModule** route described below, which
  answers barks by the event name the game posts and covers the 27 Vorbis ids above.

The BeardLib zip is a BeardLib **SoundsModule** mod: `mods/Miranda Lawson VO over Hila/` with `main.xml`
(prefix `rb21`), `mod.txt`, `README.txt` and `sounds/*.ogg`. SuperBLT (for the XAudio OGG API) and
BeardLib 5.x are hard requirements - see
[`docs/pd2-voice-mod-install.md`](../docs/pd2-voice-mod-install.md) for the full packaging contract,
install/uninstall steps. BeardLib's *Log Sounds* option is the coverage check, not a prerequisite:
it prints the id of a bark this pack deliberately leaves vanilla (see the install doc, section 4d).

> **Keying.** `main.xml` is keyed on PD2 **bark event names** (`g18`, `f11e_plu`, `f30x_any`,
> `s08x_sin`, …) with the `rb21` prefix, taken from `miranda_lawson/slot_event_ids.csv`. The numeric
> voice-line ids in `hila_intent_cuts.csv` (`712675`, `1149328`, …) are *not* what the game posts, so
> a build keyed on them loads and replaces nothing - that was the first build of this pack. Section 4
> of the install doc has the derivation of the names (PD2 Lua + the community callout sheet), why the
> `.stream` route never needs them, and how Log Sounds reveals a bark that was missed.

## Rules the tools enforce

- **No names.** No replacement clip may say "Shepard", "Commander" or "Commando" - `fit_hila_intents.py`
  filters those transcripts out and every `slot_picks.csv` window is trimmed before the name.
- **Level matching.** Each bark is peak-matched to -1.5 dBFS (+12 dB boost at most, -9 dB cut at
  most, and no gain at all under 0.5 dB) so quiet takes such as "Captain" are not swallowed next to
  loud ones; shipped peaks land in -1.9..0.0 dBFS and `slot_to_ogg.csv` records the gain applied.
- **Reproducible builds.** Every ffmpeg encode runs with `-fflags +bitexact`, so the same picks
  always produce the same clip bytes and the same `dist/Hila/*.sha256`.
- **Cuts land on silence.** Windows come from `silencedetect` breakpoints plus syllable-rate
  estimates, so a trim takes the pause that surrounds the dropped word. `splits` in
  `slot_picks.csv` splices two ranges when the unwanted word sits mid-phrase (e.g. tech.drilling
  drops "down" from "we can cut down through").

## Known gaps in the source pack

Miranda has no line for several PD2 barks; those slots keep the closest available take:

- `drop.body` ("Bag") - the pack has no "bag" at all, so it says "Those bodies,".
- `cop.hands` / `cop.drop` ("Hands up" / "Drop it") - no police vocabulary; they use "Stop" and "Don't".
- `tech.fix` ("Fix it") - nearest line is "You'll have to do it.".
- `call_teammate.hey_you` ("Hey, you") - no "hey" anywhere, so it says "you take point.".

Re-cut those slots (`slot_picks.csv`) if a matching take is ever recorded.

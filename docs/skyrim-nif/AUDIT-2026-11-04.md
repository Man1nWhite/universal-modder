## 1. `--out` (and an extracted mesh tree) crashes the build

`build_business_woman.py:224` writes `source_report.json` into `--out` **before** anything
creates that directory (the first `mkdir` on that path is line 365, for the model file):

```python
(args.out / "source_report.json").write_text(json.dumps(report, indent=2) + "\n")
```

Measured:

```console
$ .venv/bin/python tools/pd2-las/build_business_woman.py --templates "…/2b" --out /tmp/bwbuild
source: 57785 verts / 104329 tris over 20 PD2 bones
…
FileNotFoundError: [Errno 2] No such file or directory: '/tmp/bwbuild/source_report.json'
```

The same happens with the **default** `--out` whenever the meshes are already extracted
(the supported `root/meshes/Melodic/Business Woman` layout), because `mesh_root()` returns
early and never creates `build/skyrim-nif`:

```console
$ .venv/bin/python tools/pd2-las/build_business_woman.py --root /tmp/rootx --templates "…/2b"
FileNotFoundError: [Errno 2] No such file or directory: '…/build/skyrim-nif/source_report.json'
```

Second, independent bug on the same option — the bake reads the NIFs from `--out`:

```python
st.main(["--meshes", str(args.out / "meshes"), …])          # build_business_woman.py:411
```

but `mesh_root()` unpacks `4.zip` to `REPO/build/skyrim-nif/meshes` (`:165`). With any
non-default `--out` the bake therefore fails:

```console
FileNotFoundError: [Errno 2] No such file or directory: '/tmp/bwbuild/meshes/Jacket_0.nif'
```

**Impact:** the documented one-command rebuild happens to work only because `4.zip` is
unpacked into the default directory as a side effect; the `--out` option in `--help` is
dead. **Fix:** `args.out.mkdir(parents=True, exist_ok=True)` at the top of `main()`, and
pass `mesh_root(...)`'s result to the bake (`--meshes str(src)`), not `args.out/"meshes"`.
No test *executes* `main()` — `tests/test_dist_checksums.py:46` only greps the script's
source text — which is why this shipped.

## 2. The glove fix depends on an undefined mod-load order

`hooks/businesswoman_glove_adapter.lua` is the only thing that restores
`default_glove_id = "heist_default"`, re-enables `glove_adapter`, clears
`player_style_exclude_list` and sets `body_replacement.hands = false` — i.e. without it
the outfit has **no hands** (LAS 4.1.9 forces `default_glove_id = false` and
`replace_body` hides the stock hands; see `tests/fixtures/las_loader_4.1.9.lua:30`).

The hook is `Hooks:PostHook(BlackMarketTweakData, "init", …)` — the *same* class and
function LAS's own loader post-hooks — and starts with:

```lua
local ps = self.player_styles and self.player_styles["las_businesswoman"]
if not ps then return end
```

So it only works if its PostHook is registered **after** LAS's. Nothing enforces that:

* BeardLib sorts mods by `priority` only **inside one framework**
  (`Frameworks.lua: SortMods` → `ModCore.lua:82 Priority = tonumber(config.priority) or 1`).
* LAS skins install to `assets/mod_overrides/` (that is where
  `mod_overrides/Jack Cooper - Legendary Armour Skin/` lives upstream) and are loaded by a
  *different* framework than LAS itself (`mods/Legendary Armour Skins/`) — `Core.lua:
  FullyLoadFrameworks()` iterates `pairs(self.Frameworks)`, a Lua hash table, i.e.
  **unspecified order**.
* `main.xml` declares no `<Dependencies>`/priority.
* The only thing that pins the assumption is
  `tests/test_glove_behavior_lua.py:55-57` — a comment that hard-codes
  *"the pack loads after its dependency, so this is the in-game order"* — so the
  behavioural test can pass while the game fails.

**Failure mode:** LAS's loader runs first, our hook returns early, LAS's own values stand,
and the suit renders handless (exactly the bug the hook was written to fix). Each LAS
folder rename or BeardLib version that changes framework order re-breaks it.

**Fix (order-independent):** do the correction at *query* time instead of at init, e.g.
post-hook `BlackMarketTweakData.get_glove_value` (BeardLib's override) for
`las_businesswoman`, and/or run the init-time part from `BeardLib:AddDelayedCall` /
a `Hooks:PostHook(CriminalsManager, "init")` that runs after every tweak-data init.
Declaring the dependency (`<Dependencies><Dependency name="Legendary Armour Skins"/>
</Dependencies>`, which BeardLib validates via `DependenciesModule`) and a `priority` on the
`<table>` are a good second belt, but by themselves they cannot order `mods/` against
`mod_overrides/`.

## 3. The shadow caster is a full-resolution copy of the outfit

`TPP_GROUPS["shadow"]` (`build_business_woman.py:72-78`) feeds the *entire* body group to
`s_body` with every slot remapped to `shadow_caster`; nothing decimates it (the
`decimate.py` module used for the necklace is never applied here). Measured in the shipped
zip:

| drawable | verts | tris | geometry payload | topology payload |
|---|---|---|---|---|
| `g_body` / `g_body_lod1` (shared) | 57,786 | 104,355 | 4,391,808 B | 626,150 B |
| `s_body` (its own copy) | 57,786 | 104,355 | 4,391,808 B | 626,150 B |

* TPP model **10,152,550 B**, of which the shadow is **5,017,958 B = 49.4 %**.
* FPS model **2,259,325 B**: `s_body` is 963,904 + 138,176 B = **1,102,080 B = 48.8 %**.
* 2B reference (`2b.model`, body **and** head, 3,897,376 B): `s_body` = **173 verts /
  324 tris** (4,884 + 1,964 B); `fps_2b.model` the same proxy.

So the jacket, the bustier, the skirt, the 104 k-triangle body **and the beads** are all
being skin-drawn a second time for the shadow pass, at ~300× the reference's shadow cost.
Because `shadow_caster_only:SKINNED_1WEIGHT` only reads one weight per vertex while the
geometry carries three, the extra resolution cannot even be shaded correctly — it is pure
cost.

**Fix:** build the shadow from a decimated copy (cluster decimation to ~1–3 k verts, as
`decimate.decimate` already supports), or reuse the template's 173-vertex proxy. That
alone takes `businesswoman.model` from 10.15 MB to ~5.1 MB and removes a full skinned
104 k-triangle draw per heister per shadow-casting light.

## 4. `g_body_lod1` is not a LOD

The two drawables share the *same* geometry and topology section ids (`10193`, `10194`) —
verified by hashing each section payload. `object` XML then disables `g_body_lod1` anyway.
2B ships `g_body_lod1` = 1,938 verts / 2,700 tris (a real 14× reduction), so the reference
contract is "LOD1 is cheaper"; ours silently isn't.

**Fix:** either give `g_body_lod1` a decimated mesh, or stop emitting it.

## 5. The in-game checklist tests a pack that no longer exists

`docs/skyrim-nif/in-game-checklist.md`:

* items **11a–11d** ("the outfit now ships **grafted PD2 hands** … the sleeve is welded to
  the grafted hand … gloves are **not changeable** on the graft route") — the shipped pack
  is `"hands": "adapter"` and contains no hand geometry at all (the build aborts if a
  single hand-dominant vertex exists);
* item **13a** ("`mtr_hands` is declared in the FPS material config") — it is deliberately
  absent (`fps_businesswoman.material_config` has `mtr_body`, `mtr_jacket`, `mtr_jacket2`,
  `shadow_caster`);
* item **7** ("the neck stub is folded into the collar (`trim_neck`)") — `trim_neck` is
  not in the pipeline any more (`build_business_woman.py:330-343`, HANDOFF §3); the accepted
  fix is `turn_body`. `docs/skyrim-nif/PORT-PLAN.md:276` repeats the stale `trim_neck`
  order;
* item **3** still lists the necklace as something that should be visible (see #9).

A tester following this list would report "hands missing" as a regression when the pack is
behaving as designed. The (now removed) FPS-hands preview was the same leftover: it
is a before/after sheet for the **graft** route and shows hands (plus the white cuff ring)
the shipped model does not contain.

## 6. Numbers and docstrings that disagree with the code

* `docs/skyrim-nif/HANDOFF.md:30` and `tools/pd2-port/MODLOG.md:24`: *"pytest 434 passed /
  9 skipped / 1 pre-existing fail"*. Actual on this checkout:
  `1 failed, 424 passed, 10 skipped` (`tests/test_build_models.py::test_retarget_joint_errors_and_palettes`,
  `tpp RightArm: err=5.713cm` — the documented pre-existing Miranda failure, so the
  failure itself is expected; the counts are not).
* `tests/test_glove_adapter.py:22-25` states as a contract *"``body_replacement.hands``
  stays ``true`` (vanilla ``body_replacement_standard``)"*, while the shipped hook and
  `tests/test_glove_adapter.py:83-93` assert `hands = false`. Both cannot be the design;
  the docstring is the stale one.
* `bw_pack.write_pack` hard-codes `"models_present": True` (`bw_pack.py:436`) — true today,
  but it is a claim, not a check, and it is what an installer would trust.

## 7. No README/credits, and a licence statement that contradicts the source

```console
$ .venv/bin/python -m um publish check /tmp/bw/BusinessWoman_LAS
WARN  no README (install steps, requirements, credits)
WARN: 26 files, 0 failures, 1 warnings
```

`dist/lawson_las.zip` ships a `CREDITS.txt`; `BusinessWoman_LAS` ships nothing. Meanwhile
`5.zip/Please Read.txt` (the source outfit) says, first line:

> Please, do not publish this mod outside Loverslab without permission!

and `BUILD_INFO.json` records `"private": false`, `"redistribution": "published at the
pack owner's direction"`, `"source": "Melodic Business Woman SE 3BA"`. At minimum the pack
should carry a credits file naming Melodic and stating the permission status; as it stands
the tracked artifact is a redistribution of someone else's assets with no attribution
inside it. (`docs/skyrim-nif/in-game-checklist.md` already calls this out — it is a
decision, but it is an undocumented one inside the shipped folder.)

## 8. Dead 2B template materials ride along

Both models keep all seven of the template's material sections; the pack references only
its own six plus `shadow_caster`. Unreferenced leftovers in `businesswoman.model` and
`fps_businesswoman.model`:

```
0xaaf7523d2286628c, 0x8e4dc7fe01c40f8f, 0x84ea363244e1050b
0x39bb5b10f76f7412  (= hash64("mtr_body_lod1"))
0xbc54979e8db90d74  (= hash64("mtr_head"))
```

`mtr_head` surviving is the awkward one: `assemble_model(..., drop_drawables=("g_head",
"g_head_lod1"))` removes the *geometry* of the template's character so the pack can never
show her face, but her *materials* are still in the file. Harmless at runtime (no drawable
points at them) — and the `fps` unit needs the c_block material — but they should be
dropped for the TPP unit, or the intent comment should say why they are kept.

## 9. The necklace is (almost) not visible

The necklace slice is 2,686 verts / 3,484 tris sitting at z 154.9–160.6 cm, y 4.8–17.7 cm,
i.e. **inside** the blazer (z to 161.4, y to 29.1) and the bustier (z to 162.0, y to 28.0).
Occlusion test on the shipped model (render with and without the necklace, count pixels
that change, 800² per view):

| view | shipped | Skyrim source |
|---|---|---|
| front | 9 px | 19 px |
| three-quarter | 7 px | 29 px |
| side / back | 0 px | 0 px |

So this is **not a regression** (the source's choker is a collar-height chain too), but the
port pays 3,484 tris + a shadow copy + two 128² textures for ~1 % of a pixel row. Either
drop it, or re-lay it outside the bustier (and give it a bigger texture — the 128² comes
from `skyrim_materials.py:319 target = min(size, diffuse.shape[0])`, the source DDS is
128²).

## 10. Skin gloss contradicts the documented invariant

`skin_texture.py:291-293` ships a uniform `SKIN_GLOSS_BASE + SKIN_GLOSS_RANGE * 0.55` = **86**
in the diffuse alpha, and the normal map is deliberately flat
(`build_normal` → 255/128/0/128), so there is no normal-slope attenuation either.
`knowledge/games/payday-2/las-armor-skin-outfit.md` invariant 4 says skin/fabric should
keep `alpha <= 28` or be slope-attenuated, or it reads as wet plastic. The 86 was chosen
in-game to kill blotching, so this may be a deliberate trade — but the invariant and the
artifact now disagree, and the invariant is what the next agent will follow.

## 11. Icon has no mip chain

`businesswoman.texture`: 256² BC3, `mips=1`, `flags=0x81007` (no `DDSD_MIPMAPCOUNT`).
`twobee.texture`: 512² DXT1 with `flags=0xa1007`. Any UI-side downscale of a mip-less
texture has to point-sample. Cheap fix: emit the full chain
(`skyrim_materials.encode_dds` already does) instead of the single-mip `dds_encode` path.

## Verified good (checked, no mistake found)

* **Reproducible artifact.** A rebuild from a clean tree reproduces the tracked bytes
  exactly: `sha256 -> 1f1ee2e6…` — same as `dist/BusinessWoman_LAS.zip.sha256`, and the
  fixed-timestamp zip rule holds (`BUILD_INFO.json` hashes match every payload).
* **Registration contract.** `main.xml` (`<Localization>`, `<Hooks>`, `<AddFiles>` with
  `<texture>`, six `<df_nm>`, two `<unit_mat>`), the LAS table
  (`LegendaryArmours.businesswoman`, `category = "businesswoman"` = LAS
  `texture_bundle_folder`, so the icon path `guis/dlcs/businesswoman/armor_skins/
  businesswoman` is right), the localization keys and `replace_body`-but-not-`replace_all`
  (the pack has no head, so the heister's must survive) all match the 2B reference and the
  LAS 4.1.9 loader.
* **Geometry ↔ material config.** Every material a drawable references is declared
  (`mtr_body`, `mtr_jacket`, `mtr_jacket2`, `mtr_skirt`, `mtr_heels`, `mtr_necklace`,
  `shadow_caster` TPP; three + `shadow_caster` FPS), and every declared material has its
  texture pair inside the zip.
* **Atoms.** All atoms tile the index stream and the vertex array exactly (the neck-cap fan's
  outside-the-slice indices are the documented exception, `atom_problems` docstring).
* **Skinning.** Palette indices in range (max 19 of 20), all weight sums = 1.0, palette =
  `Hips, Spine×3, shoulders/arms/forearms/hands(+thumb), legs/feet` — no `Neck`/`Head`,
  which is the deliberate "neck rides Spine2" behaviour for a headless outfit.
* **Bounds.** Stored `bounds_min/max/radius` equal the decoded geometry bounds for every
  drawable (2B's own c_block still has radius 0.0 — template data, unused).
* **Textures.** All DDS are BC3/DXT5 with complete mip chains (11 levels at 1024²,
  8 at 128²), correct sizes (1398256 / 22000), normal maps in DXT5nm order
  (`R=255, B=0, G=1−y, A=x`), diffuse alpha carrying gloss, and the jacket/bustier/skirt/
  heels/body maps are visibly distinct (no cross-wired material).
* **Model height.** z −0.12 … 167.33 cm; the 12 cm stiletto was flattened onto PD2's
  flat-footed skeleton, so the soles sit at the origin as intended.

# Miranda_Busty_LAS — Mistake Audit (2026-11-05)

**Scope.** `dist/Miranda_Busty_LAS.zip` and `build/pd2-las/Miranda_Busty_LAS.zip` as shipped at `HEAD` (29 entries, `5,450,821 B`, sha256 `fb78e41571b2a862acb452f8beabef8901abd7a1e5a1667e19646880f37b892f`), the variant pipeline (`tools/pd2-las/build_busty_variant.py`, `bust_variant.py`, `las_pack.py`, `build_las.py`), tests (`tests/test_bust_variant.py`), previews (`docs/pd2-las/previews/`), CI (`.github/workflows/test.yml`), and documentation (`docs/pd2-las/CHEST-VARIANT.md`, `docs/pd2-las/HANDOFF.md`, `tools/pd2-las/README.md`).

**Method.** Every finding below was measured directly on the shipped ZIP bytes, source archive (`models/l4d2_miranda_lawson_1.zip`), `2B` reference (`references/2b.rar`), LAS 4.1.9 Lua hooks, and rendered preview sheets — no assumptions. `dist/Miranda_LAS.zip` (`5,414,012 B`, sha256 `99b9ecc7869b0e9acae3a283c5571e6a459eb318c022144b9f4e60815d216c65`) and `dist/Miranda_Busty_LAS.zip` were left untouched during this audit.

## Detailed Findings

### 1. [High · Mesh / Visual Sculpt] Pointed cone profile, abdominal rib ridges, and UV-seam sawtooth stretch

Visual inspection of `docs/pd2-las/previews/busty_compare_chest.png` (confirmed byte-identical to a fresh render of the shipped `miranda_busty.model`) and quantitative mesh measurements show three coupled sculpt defects:

1. **Pointed bullet/cone 90° silhouette (`bust_variant.py:242`, `304`).**
   Commit `a61a920` introduced `DOME_POWER = 0.5` so `dome = (1 - r²)^0.5` formed a true rounded ellipsoid cap (`docs/pd2-las/previews/side90_rounder.png`). Commit `8aa2985` then raised `DOME_POWER` to `1.6` without reducing `GAIN_Y = 11.5` or widening the core radii `(4.2, 6.2, 5.2) cm`. Because `(1 - r²)^1.6` has inflection flanks and a narrow peak, projecting `+10.73 cm` forward (`y: 19.98 → 30.71 cm`, ~45% of the `23.6 cm` torso width) turns the side silhouette into a sharp horizontal cone (`side90_final.png` and `busty_compare_chest.png`, 90° panel).
2. **Two vertical abdominal ridges below the inframammary fold (`bust_variant.py:224, 232–240`).**
   The broad support dome multiplies `RADIUS_Z_DOWN = 8.0 cm` by `SOFT_SCALE = 2.0` (`16.0 cm` below `APEX_Z = 139.0`), pushing displacement down to `z = 123` (clamped at `BAND_LO = 126.0`), while `valley(x)` (`VALLEY_DEPTH = 0.78`) suppresses `x ≈ 0` at every `z` equally:
   - `z ∈ [132.0, 134.5)` (below the base underbust fold at `z ≈ 134.5`): breast columns (`|x| ∈ [4.0, 7.5]`) still push forward **`+5.10 cm`**, while midline (`|x| < 1.5`) moves **`+1.41 cm`**.
   - `z ∈ [129.0, 132.0)` (upper abdomen / ribcage): breast columns still push forward **`+1.93 cm`** vs **`+0.60 cm`** at midline.
   In the 0°, 30°, and 90° renders this creates a secondary shelf/bulge underneath the breasts and two vertical pillars down the upper stomach, while carving a deep cleavage valley through a stiff one-piece hex-weave chest flap.
3. **Coarse unsplit strip and `3.40×` area stretch along the chest UV seam (`bust_variant.py:638`).**
   `subdivide_region` skips every triangle that touches any duplicated UV-seam vertex (`if any(v in shared for v in tri): continue`). That leaves a band of large, unsubdivided triangles running diagonally across the steepest part of each breast right next to 1-to-4 subdivided triangles:
   - Measured 3D-area inflation on unsplit chest triangles reaches **`3.40×`** (`tri=(381, 380, 371)` at `z = 147.9`), **`2.83×`** (`tri=(372, 809, 808)`), and **`2.47×`** (`tri=(819, 581, 586)`) — directly refuting `CHEST-VARIANT.md` Trap #14 (*"took the max inflation to 1.21× with zero triangles above 1.5×"*).
   - **253 of 1,139** chest triangles exceed `2.0×` the base chest median texel ratio (`p95 = 3.13×` vs base `1.33×`), producing the jagged sawtooth distortion along the stitched seam line in the 30° and 90° views.
   - *Fix:* subdivide seam edges in lockstep across welded twin vertices (interpolating each side's own UV/normal/weights separately so UV seams stay split while 3D positions stay welded) instead of skipping seam-adjacent triangles.

### 2. [High · Build / CLI] `build_busty_variant.py` crashes on clean checkouts and on `--out`, and clobbers `dist/`

1. **Hard crash when `build/pd2-las/miranda.model` is absent (`build_busty_variant.py:163, 286`).**
   `build/` is gitignored. Running the documented build command from `tools/pd2-las/README.md` / `CHEST-VARIANT.md` on a clean checkout crashes at the preview step:
   ```text
   FileNotFoundError: [Errno 2] No such file or directory: '.../build/pd2-las/miranda.model'
   ```
   `_render_sheets` hardcodes `base_model_path = args.out / "miranda.model"` instead of extracting `miranda.model` from `dist/Miranda_LAS.zip` (or building an in-memory base `ModelFile` from the pre-morph groups it already transferred at lines 224–226). Forcing the user to run `build_models.py` first also contradicts `CHEST-VARIANT.md` Trap #1 (*"The base route must not be re-run"*).
2. **`--out` crashes with `FileNotFoundError` and `ValueError`, writes wrong `.sha256` paths, and overwrites `dist/` (`build_busty_variant.py:198, 213, 319–327`).**
   - Passing `--out /tmp/mb_test` crashes on `FileNotFoundError: '/tmp/mb_test/miranda.model'`.
   - Even when `miranda.model` is present, `_render_sheets` calls `out.relative_to(REPO)` (`line 198`) on an un-resolved `args.out`: passing **either** a relative path (`--out build/pd2-las`) **or** an external path (`--out /tmp/mb_test`) raises `ValueError: '...' is not in the subpath of '<repo>'`.
   - Lines `319–320` hardcode `f"{sha}  build/pd2-las/{PACK_DIR_NAME}.zip\n"` inside `args.out / "Miranda_Busty_LAS.zip.sha256"` regardless of `args.out`.
   - Lines `321–327` unconditionally copy the built zip and checksum over tracked `dist/Miranda_Busty_LAS.zip` and `dist/Miranda_Busty_LAS.zip.sha256` even when `--out` was pointed at a scratch directory.

### 3. [Medium · Engine Asset Contract] `fps_miranda_busty.object` and `.material_config` declare stripped drawables and unused materials

- **`fps_miranda_busty.object` vs `fps_miranda_busty.model` (`build_busty_variant.py:255`, `las_pack.py:216`).**
  `build_busty_variant.py` calls `bm.assemble_model(fps_template, fps_groups, drop_drawables=("g_head", "g_head_lod1"))`, so `fps_miranda_busty.model` contains only `g_body` and `s_body`. However, `las_pack.write_pack` copies `fps_2b.object` with only unit-path string substitution, leaving:
  ```xml
  <graphic_group name="character" enabled="true" culling_object="co_box">
      <object name="g_body" enabled="true" />
      <object name="g_head" enabled="true" />
      <object name="g_head_lod1" enabled="true" />
      <object name="s_body" enabled="true" shadow_caster="true" />
  </graphic_group>
  ```
  Two enabled `<object>` nodes (`g_head`, `g_head_lod1`) do not exist in `fps_miranda_busty.model` (inherited from `build_models.py`; note that `bw_pack.render_object_xml()` at `tools/pd2-las/bw_pack.py:72–86` was written specifically to avoid dangling `.object` drawables).
- **`fps_miranda_busty.material_config` (`las_pack.py:185–190`).**
  Declares 5 materials (`mtr_body`, `mtr_face`, `mtr_head`, `mtr_hair`, `mtr_eyes`) referencing all 9 unit textures, whereas `fps_miranda_busty.model` only uses `mtr_body` (plus `shadow_caster_only` on `s_body`).
- **Residual template `MATERIAL` sections in `.model` (`build_models.py:570–617`).**
  `miranda_busty.model` carries **19** `MATERIAL` sections for 6 actual geometry materials (5 dead `2B` material sections `mtr_2b_*` / `mtr_hair_2b` + duplicate entries for all 6 Miranda materials); `fps_miranda_busty.model` carries **12** `MATERIAL` sections for 2 actual materials.

### 5. [Medium · Math / Mesh Code] Boundary discontinuity (`dx`), normal bleed, and slice-filter bug in `bust_variant.py`

1. **`dx` omits `* ceil`, creating a step discontinuity at `z = 152.0` and `z = 126.0` (`bust_variant.py:333–339`).**
   ```python
   ceil = self.ceiling(z) * self.band(z)
   dy = self.gain_y * lift * v * b * fall * ceil
   ...
   dx = sign * self.splay * min(abs(x) / 3.0, 1.0) * b * fall   # <-- missing `* ceil`
   ```
   Because the broad support dome scales `r_z` by `SOFT_SCALE = 2.0` (`22.0 cm` up to `z = 161`, `16.0 cm` down to `z = 123`), `fall` is non-zero at both hard cutoffs (`z = HEAD_Z = 152.0` and `z = BAND_LO = 126.0`):
   - Across `z = 151.999 → 152.001` (at `x = 6, y = 18`): `dy` tapers cleanly (`0.0000 → 0.0000`), but **`dx` jumps from `+0.1371 cm` to `0.0000 cm`**.
   - Across `z = 126.001 → 125.999` (at `x = 6, y = 18`): **`dx` jumps from `+0.0285 cm` to `0.0000 cm`**.
   (`CHEST-VARIANT.md:107` even writes the formula *with* `ceiling(z) * band(z)` on `dx`, showing the omission in `bust_variant.py:338` was accidental.)
2. **`weight_at()` omits `HEAD_Z` and `band(z)`, bleeding recomputed normals outside the edit band (`bust_variant.py:380–386, 513`).**
   `rebuild_normals` recomputes normals for every vertex with `morph.weight_at(*v) > 0.0`. Because `weight_at` checks neither `z >= self.head_z` nor `self.band(z)`, vertices outside `[126, 152]` that suffered `0.0 cm` displacement still have their authored source normals overwritten with flat face-area averages (measured on shipped `g_body`: **3 unmoved vertices** at `z = 125.89..125.99` had their normals altered by up to `0.0037`).
3. **`ChestMorph.apply(..., materials=...)` leaks across material slices when faces exist (`bust_variant.py:424–429, 617`).**
   - `subdivide_region` (`line 617`) unconditionally extends `group.slices[-1]` (`name, ts, tc, vs, vc + added_verts`), corrupting slice ranges if the selected material is not the final slice.
   - `smooth_region` (`line 427`) and `rebuild_normals` (`line 429`) are not passed `materials` / `allowed` at all. On a 2-slice mesh (`miranda_head` + `miranda_body`) with 2 triangles, calling `ChestMorph().apply(g, materials=("miranda_body",))` moves the excluded `miranda_head` vertices by **`0.27–1.08 cm`**. (In the current Miranda build `s_body` happens to have `miranda_body` last and `miranda_head` vertices above `z = 152`, which masked the bug.)

### 6. [Medium · Performance / Shadow Rig] Un-decimated `s_body` (`SKINNED_1WEIGHT` mismatch) and un-decimated `lod1`

- **`s_body` payload & skinning shader mismatch:**
  - `miranda_busty.model`: `s_body` contains **10,172 vertices / 17,029 triangles (`875,338 B` = `46.7%` of the entire 1.87 MB model)** — including the +298 verts / +596 tris from chest subdivision that contribute nothing meaningful to ground/wall shadow silhouettes. By contrast, `2B`'s `s_body` is a 173-vert / 324-tri capsule proxy (`6,848 B`).
  - `fps_miranda_busty.model`: `s_body` contains **1,774 vertices / 2,892 triangles (`152,268 B` = `42.1%` of the 361 KB model)**.
  - In `miranda_busty.material_config`, `shadow_caster_only` uses `render_template="shadow_caster_only:SKINNED_1WEIGHT"`, yet **5,029 of 10,172** TPP `s_body` vertices (`49.4%`) and **849 of 1,774** FPS `s_body` vertices (`47.9%`) carry 2 or 3 bone weights — risking single-bone skinning divergence between the shadow caster and the 3-weight lit body at joints.
- **Duplicate `lod1` meshes:**
  `g_body_lod1` (`5,943` verts / `10,144` tris) and `g_head_lod1` (`4,229` verts / `6,885` tris) are full-resolution copies of `g_body` and `g_head` (0% triangle reduction at distance).

### 7. [Low · UX / Menu & Packaging] Duplicate menu icon, non-ASCII localization punctuation, and missing README

1. **Byte-identical menu icon (`miranda_busty.texture` == `miranda.texture`, sha256 `6fdae459992ea035…`).**
   `Miranda_Busty_LAS` is explicitly designed to install side-by-side with `Miranda_LAS`, yet both packs render the exact same 256×256 face-crop thumbnail in the armor-skin grid (with no bust/torso framing or corner badge to tell them apart at a glance, especially when LAS `UseSkinCategories` is off). *(Note: LAS 4.1.9's `blackmarketgui.lua` / `blackmarketmanager.lua` `sub(5, -1)` icon-path resolution for `las_miranda_busty` → `guis/dlcs/miranda_busty/armor_skins/miranda_busty` was verified against upstream LAS Lua and works as intended.)*
2. **Non-ASCII em-dash in `localization/english.txt` (`las_pack.py:72`).**
   `bm_askn_miranda_busty_desc` contains UTF-8 `\u2014` (`"Miranda Lawson's iconic Cerberus outfit — busty variant."`), whereas `Miranda_LAS` uses plain ASCII. PAYDAY 2's menu bitmap fonts have limited non-ASCII punctuation coverage and can display `\u2014` as a missing-glyph box; ASCII ` - ` or `, ` is safer.
3. **No `README.txt` / `CREDITS.txt` in the archive.**
   `um publish check` flags `warning: no README in archive (recommended for ModWorkshop / Nexus uploads)` (unlike `dist/lawson_las.zip`, which includes `CREDITS.txt`).

### 8. [Low · Provenance, Previews, Tests & Documentation Drift]

1. **Broken `volume_proxy` in `BUILD_INFO.json` (`build_busty_variant.py:73–95`).**
   `_measure()` documents `volume_proxy` as *"Sum of max(0, y) over the chest band — monotone proxy for forward chest volume over the **same vertex set**"* and records `[2037.6, 7531.4]` (an apparent `3.70×` jump). In reality, `_chest_verts(before_verts)` selects **187** pre-subdivision vertices while `_chest_verts(after_verts)` selects **485** post-subdivision vertices (both because +298 midpoint vertices were appended *and* because `weight_at(x, y, z) > 0.05` is re-evaluated at the displaced `y`). Over the actual original 187 vertices, the sum goes from `2037.6` to `3050.8` (`1.50×`, not `3.70×`).
2. **Stale `ChestMorph.describe()` + dead code (`bust_variant.py:225, 250–254, 317–325, 432–445`; `build_busty_variant.py:134–144`).**
   - `BUILD_INFO.json`'s `morph` dict reports `radius_x_cm: 7.0` (`RADIUS_X`, never read anywhere in `displacement()`) instead of `[RADIUS_X_OUT=4.2, RADIUS_X_IN=9.2]`, and omits `soft_scale`, `soft_weight`, `dome_power`, and `band_z_cm`.
   - `RECEDE_Z`, `RECEDE_DEPTH`, `RECEDE_SIGMA`, `ChestMorph.recede()`, and `build_busty_variant._body_parts()` are completely unused dead code.
3. **Headless full-body preview + unreferenced scratch PNGs (`docs/pd2-las/previews/`).**

   - `tools/pd2-las/README.md:196–253` still documents the pre-subdivision v1 build (`+4.5 cm` gain, apex `z = 139.0`, `19.98 → 24.48 cm`, `volume_proxy 2037.6 → 2690.4`, *"Same topology, UVs, weights, bone palettes"*).
